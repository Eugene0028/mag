# Замеры фаз и воспроизведение экспериментов РГЗ

## Быстрый запуск

Откройте `securetransfer` в IDEA, выберите JDK 17 и конфигурацию
**SecureTransfer - RGZ TransferExperimentMain**. В консоли:

- `1` или Enter — локальная серия через TCP `127.0.0.1`;
- `2` — серия к получателю на другом компьютере, затем адрес и порт.

Размеры, число прогревов и повторов задаются именованными константами
`RgzSettings.TRANSFER_FILE_SIZES`, `TRANSFER_WARMUP_COUNT`, `TRANSFER_REPETITIONS`.
Значения по умолчанию: 0, 81, 1024, 65536, 1048576, 10485760, 67108864 байта;
два прогрева на 1 МиБ и пять повторов на размер. Каждый файл получает отдельный
MQV-сеанс с новой временной парой. Первая генерация параметров и долговременных
материалов выполняется до серии. Прогрев не означает полную стабилизацию JIT.

Программа печатает каталог `data/rgz/reports/file-transfer/<дата>-<id>/`:

- `measurements.csv` — наблюдения в наносекундах, сторона, размер, повтор,
  признак прогрева и выполненные проверки;
- `environment.txt` — ОС, JVM, архитектура, параметры и топология;
- `report.html` — медианы в миллисекундах, границы замеров, выводы и исходный CSV.

Искусственные входные и принятые файлы локальной серии удаляются только после
побайтового сравнения и сверки SHA-256. Хеши остаются в CSV. Постоянный журнал
IV `data/rgz/state/iv-sequence.log` сохраняется. Не удаляйте и не откатывайте
его при продолжении использования прежних ключей.

## Что измеряется

| Поле CSV | Граница интервала |
| --- | --- |
| `preparation_ns` | Подготовка серверного MQV до `accept`, проверки параметров, ключей и файлов доверия; без ожидания клиента |
| `connection_ns` | `Socket.connect` отправителя |
| `key_establishment_ns` | MQV, проверки доверия, SHA3 и взаимные подтверждения после подключения; серверная предварительная подготовка отдельно |
| `cipher_setup_ns` | Создание шифра и установка ключа и IV |
| `cipher_ns` | Сумма вызовов `processBytes`: шифрование у sender, расшифрование у receiver |
| `authentication_ns` | Обновление HMAC в цикле обработки; финализация тега внутри общего файлового этапа |
| `disk_io_ns` | Чтение или запись порций файла; без открытия, закрытия и `force` |
| `network_io_ns` | Сумма времени вызовов сетевых потоков, `flush`, окончания потока и подтверждения |
| `transfer_elapsed_ns` | Полный файловый этап от подготовки заголовка до отправки/получения подтверждения; включает IV, шифр, HMAC, диск, сеть и публикацию файла |

Все интервалы — **прошедшее время `System.nanoTime()`**, включая вытеснение
потока и блокировки. Сетевой ввод-вывод измерен по часам, а не по процессорным
циклам. Буферизованные `read`/`write` не показывают чистое время прохождения
пакетов. Для оценки полезной скорости берётся размер / `transfer_elapsed` sender;
это скорость всего файлового этапа, не паспортная скорость канала.

`transfer_elapsed` содержит остальные файловые интервалы. Наблюдения сторон
также перекрываются во времени. Их нельзя складывать или вычитать из них
«чистую сеть». Время `force`, операций с каталогами, резервирования IV и
финализации MAC входит в общий интервал, но не выделяется отдельными колонками.
Накладные расходы замеров не вычитаются. Сообщения валидаторов и чтение
доверенных файлов входят в подготовку и установление ключа.

Время локальной подготовки получателя не включено в клиентскую фазу MQV:
получатель готов до подключения. Для оценки последовательной подготовки всего
сеанса следует отдельно рассмотреть `preparation` receiver и `key_establishment`
sender. Медианы независимых фаз не являются медианой их суммы.

## Опыт между двумя компьютерами

1. На компьютере A запустите **FileReceiverMain**, выберите новый каталог приёма
   и порт 6060. Дождитесь сообщения об ожидании подключения. Первое создание
   параметров может занять время.
2. Передайте на компьютер B доверенным способом ровно клиентский комплект:
   `data/rgz/keys/bob-long-term.properties`,
   `data/rgz/trust/mqv-directory.properties`,
   `data/rgz/trust/authority-public.der`. Не заменяйте его независимо
   сгенерированными файлами. Секрет Алисы на B не требуется.
3. На A разрешите входящее TCP-соединение на выбранный порт. Зафиксируйте в
   описании опыта оба компьютера, ОС, JVM, тип соединения (Ethernet/Wi-Fi),
   условия нагрузки и фактический адрес A. Адрес `127.0.0.1` для этого опыта
   не подходит.
4. На B запустите **TransferExperimentMain**, режим `2`, адрес A и порт.
   Сначала выполняются два прогрева, затем пять повторов каждого размера.
   Имена файлов содержат уникальный идентификатор серии, размер и повтор.
5. Сохраните CSV/HTML/окружение обеих сторон. Получатель вычисляет SHA-256
   сохранённого файла после подтверждения, вне измеряемого файлового этапа.
   Сопоставьте строки по `file_name` и `size_bytes`, сравните SHA-256 из поля
   `verification`, исключите `warmup=true`. Удалённая серия сохраняет принятые
   файлы; исходные искусственные файлы B удаляются после положительного ACK.
6. На каждом компьютере анализируйте собственные длительности. Абсолютные
   значения `nanoTime` между компьютерами несопоставимы, синхронизация часов
   для длительностей не нужна. Повторите серию при сопоставимой нагрузке.

Успешный ACK означает проверку HMAC получателем, а не выполненное на отправителе
побайтовое сравнение удалённого файла. Для дополнительной сверки предназначены
контрольные суммы двух CSV. Удалённый режим сам по себе не доказывает, что
процессы запущены на разных физических машинах: это фиксируется условиями опыта.

### Сетевая серия Mac → Windows

19.10.2026 проведена серия между двумя физическими компьютерами одной локальной
сети; оба подключены по Wi-Fi. Файлы передаются напрямую по TCP 6060, SSH
использован для запуска получателя и сбора результатов.

| Сторона | Оборудование | Система |
| --- | --- | --- |
| Отправитель, `192.168.1.4` | Apple M4 Pro; 14 процессоров доступны JVM | macOS 15.7.9, aarch64, BellSoft JDK 17.0.19 |
| Получатель, `192.168.1.9` | AMD Ryzen 5 4500U, 6 ядер / 6 логических процессоров | Windows 10 10.0.19045, amd64, BellSoft JDK 17.0.20.1 |

Каталог серии на Mac:
`data/rgz/reports/file-transfer/2026-10-19_16-22-37-8b897d73/`.
В нём находятся:

- `measurements.csv`, `environment.txt`, `report.html` отправителя;
- `peer-receiver/` — исходные CSV, HTML и окружение получателя;
- `combined-measurements.csv` — 74 сопоставленные строки двух сторон;
- `comparison.html` — сравнение фаз и локальной серии;
- `comparison.json` — минимум, медиана и максимум пяти повторов;
- `analysis-method.txt` — правила сопоставления и исключения прогрева;
- `windows-hardware.json` — сведения о CPU, ОС и Wi-Fi Windows;
- `sent-report-verification.json` — проверка пробной передачи Word-отчёта;
- `source-code.zip` — использованный исходный код с библиотеками, без ключей.

Все 35 измеряемых и 2 прогревочные передачи завершились проверенным ACK.
Для каждой из 37 пар совпали имя, размер, повтор, признак прогрева и SHA-256.
Побайтовое сравнение удалённых файлов отдельно не выполнялось. Исходный CSV
получателя содержит ещё одну пробную передачу Word-отчёта; она исключена из серии.

Получатель был запущен с рабочим каталогом `C:\Users\User\Desktop\mag`, поэтому
его данные расположены в `C:\Users\User\Desktop\mag\data\rgz`, а не внутри
вложенной папки `securetransfer`. Mac использует рабочий каталог `securetransfer`.
Windows создал собственные параметры MQV 3072/256 бит. Клиентские файлы Bob и
подписанного справочника перенесены на Mac и проверены. Числовые параметры группы
отличаются от локального опыта при тех же битовых размерах.

Для 64 МиБ медиана полного файлового этапа отправителя составила **5616,635 мс**,
полезная скорость — **11,39 МиБ/с**, отношение к локальным 270,341 мс — **20,78**.
Это скорость всей обработки до ACK. Установленный адаптером Windows режим
292,5 Мбит/с не является измерением полезной скорости. Сравнение включает разные
процессоры, версии JVM, накопители и сетевые условия; вклад каждого фактора
отдельно не выделен. Фазы сторон перекрываются, их длительности не складываются.

### Показательная передача с чтением содержимого

Отдельный запуск 19.10.2026 сохранён в
`data/rgz/reports/demonstration/2026-10-19_17-03-57/`.
Текстовый файл UTF-8 размером 362 байта прочитан через `cat` на Mac, передан
FileSenderMain и прочитан через `cat -Encoding UTF8` в PowerShell Windows по SSH.
Совпали SHA-256 и все байты исходной и принятой копий. Приложение выполнило
прямую передачу по TCP 6060 с MQV и Sosemanuk; SSH использовался для управления
и чтения принятого файла. Этот запуск не включён в статистику 35 передач.

В каталоге находятся `transcript.txt`, полные логи приложения, вывод двух `cat`,
CSV и окружение обеих сторон, исходная и прочитанная копии. Принятый файл
оставлен на Windows:
`C:\Users\User\Desktop\mag\received\securetransfer-demo-2026-10-19_17-03-57.txt`.
Подраздел 8.6 общего Word-отчёта содержит вывод команд и ключевые строки логов.
