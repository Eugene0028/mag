# SecureTransfer — лабораторная работа 1

DH в полной группе, DH в подгруппе простого порядка и MQV: локальный обмен,
обмен по TCP и замеры основных вычислений в процессорных циклах.

## Требования

- **JDK 17** — компиляция и запуск Java-кода.
- **IntelliJ IDEA** — открытие проекта и запуск готовых конфигураций.
- **JNA 5.17.0** — уже находится в `lib/jna-5.17.0.jar` и подключена в модуле.

Арифметика больших чисел реализована через стандартный `BigInteger`.
JNA вызывает системные функции счётчиков процессорных циклов.
Её лицензия находится в `lib/JNA-LICENSE.txt`.

## Запуск в IDEA

1. Откройте папку `securetransfer` как проект.
2. Выберите установленный **JDK 17** в качестве SDK проекта. Модуль использует SDK проекта.
3. Запустите конфигурацию **SecureTransfer - LauncherMain** и выберите пример в консоли.

В настройках запуска рабочей папкой должна быть папка `securetransfer`.
Готовые конфигурации уже используют её.

Отдельные примеры также запускаются напрямую:

| Класс | Назначение |
| --- | --- |
| `FullGroupDhMain` | Локальный DH в полной группе |
| `SubgroupDhMain` | Локальный DH в подгруппе |
| `MqvMain` | Локальный MQV |
| `network/KeyAgreementServerMain` | Сервер с выбором алгоритма |
| `network/KeyAgreementClientMain` | Клиент |
| `BenchmarkMain` | Прогрев JVM и повторные замеры |

## Сетевой обмен

1. Запустите `KeyAgreementServerMain`.
2. В консоли сервера выберите алгоритм: 1 — DH полной группы, 2 — DH подгруппы, 3 — MQV.
3. Дождитесь сообщения «Сервер ожидает подключение на порту 5055».
4. Запустите `KeyAgreementClientMain`.
5. Сравните общий секрет в обеих консолях.

Клиент получает выбор алгоритма от сервера. Сервер обслуживает одно подключение
и завершает работу; для нового обмена запустите его снова.
В учебных примерах используются маленькие числа: p — 16 бит, q подгруппы — 8 бит.

По умолчанию клиент подключается к `127.0.0.1:5055`.
Для двух компьютеров в одной локальной сети укажите адрес сервера в общем меню
или в **Program arguments** конфигурации клиента: `192.168.1.10 5055`.
Серверу можно передать порт, например `5056`.
Брандмауэр компьютера с сервером должен разрешать входящее подключение на выбранный порт.

### Подготовка MQV

Сервер представляет Алису, клиент — Боба. При первом выборе MQV сервер подготавливает:

| Файл | Содержимое |
| --- | --- |
| `data/keys/alice-long-term.properties` | Секретная и открытая долговременная пара Алисы |
| `data/keys/bob-long-term.properties` | Секретная и открытая долговременная пара Боба |
| `data/trust/mqv-directory.properties` | Подписанный справочник открытых ключей |
| `data/trust/authority-public.der` | Доверенный открытый ключ центра для проверки подписи |

Долговременные пары и справочник используются повторно, временные пары создаются
для каждого обмена. Секретный ключ учебного центра применяется при подготовке подписи
и остаётся только в памяти. Неполный или несовместимый набор файлов вызывает ошибку.

На одном компьютере оба процесса читают общую папку `data/`.
Для запуска на двух компьютерах заранее передайте клиенту по доверенному каналу:

- `data/keys/bob-long-term.properties`;
- `data/trust/mqv-directory.properties`;
- `data/trust/authority-public.der`.

Сохраните относительные пути в рабочей папке клиента.
Параметры группы клиент получает от сервера и проверяет по справочнику.
По TCP передаются алгоритм, открытые параметры и открытые ключи.
Секретные ключи и общий секрет выводятся только локально в учебных примерах.

## Замеры — пункт 19

Запустите `BenchmarkMain` без аргументов или выберите пункт **6** общего меню.
Настройки собраны в именованных константах `measurement/BenchmarkSettings`:

| Настройка | Значение |
| --- | --- |
| Длина p | 1024 бита |
| Длина q подгруппы | 160 бит |
| Прогрев каждого этапа | 1000 операций |
| Число замеров этапа | 100 |
| Операций в одном замере | 10 |

Для q длиной 256 бит измените `DEFAULT_SUBGROUP_ORDER_BIT_LENGTH` на `256`.
Параметры замеров хранятся в `data/params/benchmark/` отдельно от маленьких учебных
параметров. Первая генерация большого простого p может занять время.

Для каждого алгоритма измеряются три этапа одного участника:

1. Генерация секретного ключа.
2. Вычисление открытого ключа.
3. Вычисление общего секрета.

DH в подгруппе и MQV используют одну подгруппу.
Для открытых и общих ключей заранее готовятся 64 различных набора входа,
используемых по кругу. Секретный ключ при измерении генерации каждый раз выбирается заново.
Долговременные ключи MQV, подпись справочника и её проверка подготавливаются заранее.
Вырожденные временные пары MQV отбрасываются при подготовке: измеряется успешное вычисление
секрета без стоимости повторного выбора ключей. Совпадение секретов проверяется до замеров.

Файлы, сеть, проверка параметров и консольный вывод находятся вне измеряемых интервалов.
Оба чтения счётчика и вычисление выполняются в одном потоке.
Каждый полученный результат используется после второго чтения счётчика.
Финальное хэширование в этой лабораторной пока не применяется.

Программа выводит медиану, среднее, минимум и максимум циклов на операцию.
Это статистика стоимости серий, делённой на число операций в серии.
Исходные циклы серий сохраняются в объектах `StageMeasurement`, затем записываются в CSV.
Пустая серия показывает служебные затраты отдельно, без автоматического вычитания.
Фиксированный прогрев не гарантирует установившуюся производительность JVM;
сборка мусора и фоновая нагрузка могут влиять на разброс.

### Отчёт — пункт 20

После успешного завершения всех девяти этапов `BenchmarkMain` автоматически создаёт:

```text
data/reports/<дата-время-идентификатор>/
├── measurements.csv
└── report.html
```

Пути к обоим файлам выводятся в консоли. Откройте `report.html` обычным браузером:
в нём есть сравнительная таблица, выводы по фактическим медианам, условия запуска
и отдельное описание служебных затрат. Кнопка «Печать / PDF» использует печать браузера.
Каждый запуск получает новую папку; предыдущие результаты сохраняются.

CSV содержит исходные целочисленные циклы серий. Столбцы:
`kind,algorithm,stage,measurement_index,operations,cycles`.
Тип `stage` обозначает этап алгоритма, `overhead` — пустую операцию.
При стандартных настройках сохраняется 1000 строк данных: 900 для этапов и 100 служебных.
Для перехода к циклам на операцию используется `cycles / operations`.

`BenchmarkReportWriter` сначала сохраняет CSV через `BenchmarkCsvFileStorage`,
затем перечитывает его и по восстановленным показаниям строит таблицу и выводы.
HTML содержит оформление и текстовую копию исходного CSV; интернет и веб-сервер
для просмотра не требуются. Ссылка на отдельный CSV работает, пока оба файла лежат рядом.
В отчёте сохраняются размеры p/q, настройки прогрева, ОС, архитектура JVM,
версия Java и описание счётчика. Секретные ключи в эти файлы не записываются.

HTML-шаблон находится в `src/main/resources/benchmark-report.html`.
Эта папка отмечена в модуле IDEA как ресурсы и копируется при сборке.
Редактировать оформление можно отдельно от Java-кода.

Выводы сопоставляют одинаковые этапы в одном запуске. Они не устанавливают
статистическую значимость и не описывают длительность полного сетевого сеанса.
Для коротких вычислений отдельно отмечается масштаб служебных затрат.

### Системные счётчики

Поддерживаются macOS, Windows и Linux на x86-64 и ARM64. JNA выбирает нативный адаптер
для архитектуры запущенной Java.

| Реализация | Системный API | Область учёта |
| --- | --- | --- |
| `MacOsCpuCycleCounter` | `thread_selfcounts` | Аппаратные циклы потока; macOS 12.4+ и поддержка оборудования |
| `WindowsCpuCycleCounter` | `QueryThreadCycleTime` | Циклы потока, включая режим ядра; трактовка тактов зависит от CPU |
| `LinuxCpuCycleCounter` | `perf_event_open` | Аппаратные циклы потока без ядра и гипервизора |

Доступность зависит от оборудования и разрешений ОС. Например, Linux может запрещать
perf обычному пользователю. При недоступности счётчика программа сообщает причину;
локальные алгоритмы и сетевой обмен запускаются независимо.
Сравнивать результаты следует на одной машине, в одной ОС и с одной реализацией счётчика.

## Откуда читать код

- Локальный DH: `FullGroupDhMain` → `DiffieHellman`.
- Локальный MQV: `MqvMain` → `MqvProtocol` → `Mqv`.
- Сеть: `KeyAgreementServerMain` → `KeyAgreementProtocolFactory` → `KeyExchangeTransport` → `KeyAgreementClientMain`.
- Замеры: `BenchmarkMain` → `KeyAgreementBenchmark` → `BenchmarkRunner` → `StageMeasurement`.
- Отчёт: `BenchmarkReportWriter` → `BenchmarkCsvFileStorage` → `src/main/resources/benchmark-report.html`.
