# Библиотеки и выбор реализаций для РГЗ

## Решение по пункту 6

Для криптографических вычислений РГЗ используются Java-реализации. Версии
библиотек зафиксированы; их исходники подключены в `securetransfer.iml`.
В IDEA переход к библиотечному классу открывает соответствующий исходник.
Общий код проекта продолжает находиться в `src/main/java/securetransfer/common`.
Интерфейс потоковых шифров и их реализации находятся в
`src/main/java/securetransfer/rgz/cipher`, поскольку относятся к РГЗ.

| Шифр | Выбранная реализация | Ключ в РГЗ | IV в РГЗ |
| --- | --- | --- | --- |
| HC-128 | `org.bouncycastle.crypto.engines.HC128Engine`, Bouncy Castle 1.86 | 16 байт | 16 байт |
| Rabbit | Собственный Java-класс по описанию алгоритма в RFC 4503, пункт 9 плана | 16 байт | 8 байт |
| Salsa20/20 | `org.bouncycastle.crypto.engines.Salsa20Engine`, Bouncy Castle 1.86; 20 раундов | 16 байт | 8 байт |
| Sosemanuk | `com.coderslagoon.crypto.estreamj.ciphers.sosemanuk.Sosemanuk`, eSTREAMJ 2.0.0 | 16 байт | 16 байт |

Выбран один размер ключа для всех четырёх реализаций — 128 бит. Bouncy Castle
также поддерживает 256-битный ключ Salsa20, но для этих экспериментов выбран
128-битный вариант. Реализация Sosemanuk в eSTREAMJ сообщает размер ключа
16 байт; возможности самого алгоритма шире возможностей этого класса.

Bouncy Castle предоставляет HC-128 и Salsa20 через низкоуровневый API:
достаточно создать нужный engine и передать ему параметры. Регистрация
глобального JCA-провайдера для этого API не требуется.

Опубликованный архив eSTREAMJ 2.0.0 содержит Sosemanuk, но не содержит Rabbit
и HC-128. Rabbit реализован в исходниках проекта по RFC 4503, где
описаны установка ключа, установка IV и генерация потока, а также приведены
контрольные значения. В проект добавлены зависимости и исходники. Четыре класса
пакета `securetransfer.rgz.cipher` реализуют интерфейс `StreamCipher`:
`Hc128Cipher`, `RabbitCipher`, `Salsa20Cipher`, `SosemanukCipher`.

## Что учесть при создании общего интерфейса

Инициализация Bouncy Castle принимает ключ и IV одним вызовом `init`.
eSTREAMJ предоставляет отдельные `setupKey` и `setupNonce`. Общая сравниваемая
фаза инициализации должна включать подготовку обоих значений у каждого шифра.
Простое сохранение массива ключа в адаптере не является выполнением развёртки
ключа и не должно выдаваться за стоимость криптографической инициализации.

В Sosemanuk из eSTREAMJ длина обычного вызова `process` должна быть кратна
80 байтам; произвольная длина разрешена только для последнего вызова. Адаптер
`SosemanukCipher` сохраняет остаток ключевого потока между вызовами и принимает
порции файла произвольной длины. В `setupKey` этой реализации передаётся отдельный
массив ровно из 16 байт с нулевым смещением; на пустой `reset` полагаться нельзя.
Подготовка нового ключа создаёт новое состояние; отдельная установка IV
использует подготовленные ключевые подключи.

19.10.2026 в эксперименте проверены обработка целиком и порциями (в том числе
0, 1, 79, 81 и 65536 байт) и обратное преобразование массива 131153 байта для
всех четырёх адаптеров. Rabbit дополнительно совпал со всеми 48 байтами каждого
из трёх примеров RFC 4503, приложение A.2, с преобразованием порядка байтов.
Это ограниченная проверка, а не полная проверка соответствия всех алгоритмов
официальным наборам векторов. Результаты сохранены рядом с замерами передачи.
